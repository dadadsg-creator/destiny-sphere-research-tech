==========================
	СИСТЕМА РЕПЛИКАЦИИ
==========================

В базе для своих нужд использует таблицы в базе мастер
	ds_replication - непосредственно реплицируемые данные
	ds_replication_slaves - список подчиненных баз
 
Описание алгоритма: 
	В базе мастер на тригеры повешено логирование изменений в таблицах
  	эти изменения заносятся в виде: 
  		ТАБЛИЦА - название таблицы, в которой произошло изменение, 
  		НАЗВАНИЕ_ПОЛЯ - поле по которому идентифицируется запись в таблице, 
  		ЗНАЧЕНИЕ_ПОЛЯ - значение этого поля, 
  		ДЕЙСТВИЕ - I = INSERT, U = UPDATE и D = DELETE
	
  	берется пачка таких записей и нужные данные переносятся на подчиненные базы, 
  	т.е. выполняется дейтсвие в определенной таблице где заданное поле имеет нужное значение.
  	

Скрипт репликации запускается по крону, и живет пока не достигнет предела времени выполнения.

Все настройки задаются в основном классе SU_ReplicationControl.

Во время жизни к скрипту репликации можно подключится снаружи и узнать его состояние.
Для этого надо присоединиться с локали по протоколу tcp к порту 7375.

Поддерживаемые команды (все команды - один символ):
	'Q' - Завершение работы
	'P' - Пауза
	'I' - Информация о текущем состоянии системы, уже отформатированная
	'R' - Продолжить работу, выйти из паузы
	'T' - запрос статуса
	'D' - неотформатированая информация

==========================
		УПРАВЛЕНИЕ
==========================

Возможные статусы репликации:

	OK - репликация работает
	ERROR - репликация не работает (или не приконектиться, что маловероятно)
	PAUSE - репликация приостановлена
	STOP - репликация остановлена (скоро статус смениться на ERROR :) )


Панель управления репликацией позволяет *:

	1) просмотреть текстовый лог ("Replication log file")
	2) просмотреть и отредактировать список подчиненных баз ("Slave list")
	3) просмотреть и отредактировать список реплицируемых таблиц ("Slave tables")
	4) приостановить репликацию **
	5) остановить репликацию **
	
	
При добавлении таблицы для репликации нужно выбрать поле в таблице, которое является уникальным. Если в таблице нет уникальных полей
(или оно на нескольких полях), то репликация работать не будет, не нужно добавлять такие таблицы, иначе данные в подчиненных базах будут некоректные.

* некоторые пункты могут быть не доступны, в зависимости от статуса
	
** при следующем запуске, скрипт будет работать как обычно, чтобы скрипт не запускался можно создать 
файл Replication.stop или Replication.pause (путь см. в параметрах скрипта)
