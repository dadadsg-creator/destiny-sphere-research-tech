# Технологический стек 1

Первый вертикальный срез новой графической системы DestinySphere: модульный жилой комплекс Воранеров на настоящей сетке HTML5-клиента.

Первая принятая контрольная точка — жильё Воранеров уровня 1: простые одиночные дома и визуальные объединения `3 → 1` и `7 → 1`.

Подпроект проверяет, что утверждённое визуальное направление можно воспроизвести в реальном клиенте без изменения серверной механики, протокола и правил размещения зданий.

## Цель

Собрать на семи соседних клетках рабочий жилой квартал Воранеров, в котором:

- каждая клетка остаётся отдельным игровым объектом;
- соседние совместимые здания визуально объединяются в комплекс;
- отдельное здание можно выбрать, улучшить, отключить или снести;
- архитектура устойчиво восстанавливается после перезагрузки;
- сетка скрыта в обычном режиме и появляется только по игровому действию;
- результат сохраняет качество утверждённых концептов на Full HD и 2K.

## Границы первого этапа

Входит в работу:

- новая система представления построек поверх существующей сетки из 217 клеток;
- визуальное объединение соседних жилых зданий;
- стандарт графических ассетов и метаданных;
- сортировка по глубине, контактные тени и анимированный слой свечения воды, окон и стазиэнергии;
- детерминированные варианты архитектуры;
- проверка шести характерных конфигураций комплекса;
- изолированный прототип, который позднее подключается к `client`.

Не входит в первый этап:

- изменение серверных сущностей здания и клетки;
- переписывание игрового протокола;
- полный комплект всех построек трёх рас;
- новая боевая система;
- окончательный мобильный интерфейс;
- изменение замороженного каталога `old-sphere`.

## Основное решение

Используется гибридная 2.5D-система:

1. Здания моделируются и освещаются вне браузера.
2. В клиент поставляются прозрачные растровые слои основного цвета и свечения; падающая тень вычисляется по альфа-силуэту, а физический слой из Blender используется для проверки.
3. PixiJS размещает их на существующих координатах клеток.
4. Алгоритм объединяет соседние здания только визуально.
5. Preact продолжает отвечать за HUD и функциональные окна.

Комплекс не становится новой серверной сущностью. Это представление связной группы существующих зданий.

## Первый пилот

Пилотная конфигурация — семь клеток: центральная клетка и шесть соседей.

Минимальный комплект графики:

- 3 варианта отдельного жилого здания;
- соединительный переход для грани клетки;
- общий внутренний двор;
- внешний угловой модуль;
- центральный шпиль комплекса;
- контактная тень;
- слой голубого свечения;
- состояния строительства, работы и отключения.

## Связь с текущим клиентом

Текущий HTML5-клиент остаётся источником:

- координат и индексов клеток: `client/src/map/hexGrid.ts`;
- серверных записей построек: `client/src/map/buildData.ts`;
- соответствия типов зданий: `client/src/map/buildingTypes.ts`;
- рендера сцены: `client/src/map/renderer.ts`;
- HUD и игровых окон: `client/src/ui`.

Экспериментальный код сначала создаётся в `prototype`. В `client` переносятся только проверенные части после выполнения критериев приёмки.

## Рабочие правила

- Не изменять `old-sphere`.
- Не менять серверный идентификатор, уровень и состояние здания ради графики.
- Не определять игровой объект по имени файла изображения.
- Падающую тень строить только по альфа-силуэту ассета и зафиксированной модели света `220° / 33°`; значения цвета PNG в расчёте формы не использовать.
- Все случайные варианты вычислять из постоянного seed.
- Одинаковая входная карта должна всегда давать одинаковую архитектуру.
- Любая клетка комплекса должна сохранять отдельное выделение и действие.
- На первом уровне жилья используются только одиночный дом, `3 → 1` и `7 → 1`; более сложные или промежуточные конгломераты пока не создаются.
- Мастер-файлы не перезаписываются экспортами.
- Художественное направление сверяется с `docs/art-reference-register.md`; отбракованные попытки полного поля не используются как референсы.
- Каждый новый графический элемент должен пройти проверку якоря, масштаба, перекрытия и памяти.

## Порядок работы

1. Зафиксировать геометрию и контракт ассетов.
2. Реализовать вычисление связных групп и соседних граней.
3. Проверить алгоритм на технических формах.
4. Подготовить первый художественный набор Воранеров.
5. Подключить тени, свечение и сортировку.
6. Проверить игровые состояния и перестроение комплекса.
7. Провести визуальную и производительную приёмку.
8. Подготовить план переноса в основной клиент.

## Запуск технического стенда

Из каталога `prototype`:

```powershell
python -m http.server 4174 --directory ..
```

Открыть `http://127.0.0.1:4174/prototype/`. Стенд не требует установки пакетов.

PNG-шаблон ячейки воспроизводимо пересобирается из корня подпроекта:

```powershell
python tools/generate_cell_template.py
```

Диагностические пакеты здания пересобираются командой:

```powershell
python tools/generate_diagnostic_packages.py
```

Текущее состояние подробно отмечается в [CHECKLIST.md](CHECKLIST.md).
