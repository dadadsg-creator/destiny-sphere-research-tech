# Контракт графического ассета

## Единицы и координаты

Существующая клетка клиента имеет логический bounding box `48 × 26`.

- начало клетки: левый верхний угол;
- нижняя вершина и базовый anchor здания: `(24, 26)`;
- здание может быть физически шире клетки, но его функциональное основание принадлежит одной клетке;
- соединительные порты располагаются в серединах шести граней.

В метаданных PNG `anchor.y` измеряется по устойчивой линии фактического контакта корпуса с грунтом. Использовать одно значение для изображений с разными прозрачными полями запрещено: ошибка anchor визуально отделяет падающую тень от здания.

Логический размер не должен зависеть от количества пикселей исходного файла.

## Мастер и экспорт

Рекомендуется хранить:

- мастер-сцену Blender;
- мастер-рендер не менее `1024 × 1024` для высокого здания;
- экспорт основного слоя с прямым альфа-каналом;
- отдельные монохромные или цветные слои тени и свечения;
- оптимизированный вариант для клиента;
- половинный вариант для слабых устройств.

## Слои

| Слой | Назначение | Режим |
|---|---|---|
| `color` | Запечённый материал, свет и AO | normal |
| `shadow` | Контактная тень на поверхности | multiply/normal alpha |
| `castShadow` | Необязательная физическая тень из 3D-сцены для калибровки и особых ассетов; рабочая тень клиента вычисляется по альфа-силуэту `color` | multiply/normal alpha |
| `emissive` | Окна и энергия | add/screen |
| `construction` | Состояние строительства | normal |
| `disabled` | Отключённое состояние | normal или color matrix |
| `damage` | Повреждения, если нужны механике | normal/add |

Не применять тяжёлые размытия отдельно к каждому зданию. Мягкость должна быть подготовлена в исходном слое.

Один слой `construction` разрешено переиспользовать несколькими одноклеточными вариантами одной расы и уровня. При его наличии он полностью заменяет `color` до завершения строительства и использует собственный общий anchor по видимой линии контакта с грунтом. Полупрозрачный `color` готового здания под стройплощадкой не рисуется.

## Именование

```text
tech/residential/
├── residential-v01-color.webp
├── residential-v01-shadow.webp
├── residential-v01-emissive.webp
├── residential-v02-color.webp
├── connector-edge-color.webp
├── connector-edge-emissive.webp
├── courtyard-color.webp
├── centerpiece-color.webp
└── residential.json
```

Рекомендуемый ключ ассета не содержит уровень игрока или номер клетки.

## Метаданные

Пример:

```json
{
  "id": "tech/residential/v01",
  "race": "tech",
  "complexGroup": "residential",
  "footprint": [1, 1],
  "logicalWidth": 82,
  "anchor": [0.5, 0.94],
  "shadowOffset": [0, 2],
  "emissiveOffset": [0, 0],
  "ports": [true, true, true, true, true, true],
  "layers": {
    "color": "residential-v01-color.webp",
    "shadow": "residential-v01-shadow.webp",
    "emissive": "residential-v01-emissive.webp"
  }
}
```

Формальная схема расположена в `schemas/building-visual.schema.json`.

Пути слоёв разрешаются относительно самого файла манифеста. Рендер не выводит тип, уровень или вариант здания из имени картинки.

## Художественные ограничения пилота

- белая керамика и светлый металл;
- сапфировое стекло;
- голубое энергетическое свечение;
- тонкие золотые элементы;
- интегрированные растения и вода;
- один доминирующий силуэт на клетку;
- отсутствие мелкой детали, превращающейся в шум при масштабе карты;
- читаемый вход или функциональная сторона здания.

## Проверка экспорта

Каждый файл проверяется на:

- отсутствие цветной каймы вокруг альфа-канала;
- одинаковую камеру и направление света;
- правильный anchor;
- совпадение портов соединения;
- отсутствие обрезанных высоких деталей;
- читаемость при фактическом размере в клиенте;
- разумный размер GPU-текстуры.
