# Правила формирования комплексов

## Основной принцип

Комплекс — связная компонента клеток с совместимым `complexGroup`. Он существует только в визуальном слое.

Пример совместимости:

```text
RESIDENTIAL_BUILDING ┐
VILLAGE              ├─ complexGroup: residential
CITY                 ┘
```

На первом пилоте совместимым считается только один выбранный тип жилого здания. Расширение на семейство выполняется после проверки читаемости.

## Соседство

Для каждой клетки используются шесть направлений существующей гекс-сетки. Бит направления устанавливается, если сосед:

1. существует;
2. занят зданием;
3. имеет совместимую группу;
4. допускает соединение в своём текущем состоянии.

```ts
mask |= 1 << direction;
```

Маска находится в диапазоне `0..63`.

## Уменьшение количества графики

Не создаётся 64 готовых изображения здания. Используются:

- базовый модуль клетки;
- один переход, вращаемый на шесть направлений;
- элементы внешнего периметра;
- внутренний двор;
- центральный элемент комплекса;
- несколько вариантов декора.

Маски приводятся к канонической форме вращением. Отражение допускается только для симметричных художественных модулей.

## Связные компоненты

Группы вычисляются обходом в ширину или глубину. Устойчивый идентификатор:

```text
<location>:<complexGroup>:<минимальный cell.num>
```

Он используется для выбора общего варианта и центрального элемента.

## Выбор центра

Приоритет:

1. клетка с максимальным числом соседей внутри группы;
2. минимальная сумма расстояний до остальных клеток;
3. минимальный `cell.num` как стабильное разрешение равенства.

Центральный шпиль не меняет тип здания и не получает отдельную игровую механику.

## Детерминированные варианты

Seed включает:

```text
worldId + location + sotaId + complexGroup + cell.num
```

Вариант конкретной клетки не должен зависеть от порядка ответа сервера. Общий декор комплекса зависит от устойчивого идентификатора группы.

## Игровые состояния

- Строящееся здание может участвовать в фундаменте, но показывает строительный модуль.
- Отключённое здание остаётся частью формы, но теряет свечение.
- При сносе клетки соединения соседей удаляются.
- Улучшение меняет только модуль выбранной клетки, если уровень не является условием общего центра.
- Выделение всегда рисуется под конкретной клеткой.

## Недопустимые эффекты

- перенос клика на весь комплекс;
- скрытие входных данных отдельного здания;
- случайная перестройка после перезагрузки;
- соединение через пустую клетку;
- визуальный мост через несовместимое здание;
- центральный элемент, который выглядит как дополнительное игровое здание.
