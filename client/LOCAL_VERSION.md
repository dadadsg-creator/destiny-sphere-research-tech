# Наша локальная версия HTML5-клиента

Состояние на 2026-10-07.

## Источник и граница ответственности

Исходный HTML5-клиент Максима используется как рабочая основа и источник совместимости с действующей игрой. Репозиторий Максима доступен только для чтения. Все изменения этой версии выполняются локально в `D:\ProjektDS\client`.

Запрещено отправлять изменения, ветки, теги или pull request в `milmax111/Destiny-Sphere`. Ограничение и локальная Git-защита описаны в корневом `AGENTS.md`.

## Локальный запуск

```powershell
cd D:\ProjektDS\client
npm run dev -- --host 127.0.0.1 --port 5173
```

Если порт занят уже запущенной копией, Vite выбирает следующий свободный порт. Проверенная производственная сборка:

```powershell
npm run build
```

## Что уже есть в клиенте

- Vite и TypeScript собирают приложение.
- Preact отвечает за HUD, окна и игровые панели.
- PixiJS рисует карту, здания и боевой экран.
- `src/protocol/` реализует обмен с действующим сервером.
- `src/liveApp.ts` связывает серверные события, HUD и карту.
- `src/map/hexGrid.ts` точно повторяет исходную сетку из 217 клеток и их серверные индексы.
- `src/map/renderer.ts` является основной точкой замены старой графики новой системой визуализации.
- `BuildRecord` в `src/map/buildData.ts` остаётся игровым контрактом отдельной клетки.

## Правило переноса нашей графики

Игровую механику и серверный протокол не переписываем ради графики. Новая система подключается за интерфейсом рендера карты:

1. Серверные `BuildRecord` и 217 интерактивных клеток остаются независимыми игровыми сущностями.
2. Раса, тип здания, состояние клетки и соседство определяют визуальный пакет.
3. Конфигурации `3 → 1` и `7 → 1` заменяют несколько спрайтов одним комплексом только визуально.
4. Выбор, строительство, улучшение, отключение и снос продолжают работать с каждой исходной клеткой.
5. Слои сцены собираются в порядке: окружение, поверхность, тени на земле, здания, тени на соседних зданиях, эмиссия и вода, выделение клетки и служебные оверлеи.
6. Художественные параметры, манифесты зданий, тени и эффекты берём из `технологический стек1`, а не дублируем вручную внутри большого файла рендера.

## Стартовые грунты локаций

Логический тип грунта хранится независимо от художественной подложки:

- `NEUTRAL`: 217 клеток песка/пустыни (`D`).
- `CENTRAL`: 28 доступных клеток — 16 земли (`S`) и 12 скал (`R`). Остальные позиции полной 217-элементной сетки заняты служебными кодами границы (`E`) и тумана (`F`).
- После входа в мир авторитетным источником остаётся строка `<sota>` из серверного `refresh`; стартовые карты используются как проверенный fallback и для автономных стендов.

Точные константы находятся в `src/map/locationGround.ts`. Новая графика может скрывать клеточные швы, но не должна менять тип грунта, доступность клетки или правила строительства.

## Первый этап интеграции

Следующий практический шаг — вынести в локальный клиент адаптер визуальных пакетов и подключить к нему один тип: жильё Воранеров первого уровня. Сначала должны заработать одиночный дом, комплекс `3 → 1`, комплекс `7 → 1`, состояния строительства и отключения. После проверки этого вертикального среза переносим остальные здания и расы.

Первый автономный вертикальный срез доступен по `?screen=hive-217`. Он использует полную сетку из 217 активных клеток, одну общую подложку, полупрозрачную защитную сферу, контекстное управление строительством, заморозку зданий и визуальные объединения `3 → 1`/`7 → 1`. На стенде восстановлен полный HUD клиента и включён отдельный анимационный слой воды и эмиссии с лимитом 20 кадров в секунду. Детали и ограничения производительности находятся в `технологический стек1/docs/hive-217-experiment.md`.

## Известное ограничение сборки

Текущий основной JavaScript-бандл после минификации составляет примерно 633 КБ. Это не мешает первому графическому вертикальному срезу. Перед массовым подключением расовых пакетов нужно разделить интерфейсные окна и тяжёлые подсистемы через динамические импорты.
