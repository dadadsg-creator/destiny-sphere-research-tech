# CLAUDE.md

Инструкции для Claude Code (или любого другого AI-ассистента), работающего в этом репозитории.

## Что это за проект

**Destiny Sphere** («Сфера Судьбы») — российская браузерная MMO-стратегия
(Flash-клиент + PHP-бэкенд), живая с 2003 года. Этот репозиторий используется
для архивации и документирования легаси-кодовой базы перед планируемым
ремастером. Полный контекст: [docs/README.md](docs/README.md), [README.md](README.md).

## Структура репозитория

- `old-sphere/` — вся легаси-кодовая база, как она есть на живом хостинге.
  Относитесь к ней как к **замороженному историческому артефакту**,
  который документируется, а не активно разрабатывается — не рефакторьте
  и не "причёсывайте" код здесь без явной просьбы. Если начнётся работа над
  ремастером, он, скорее всего, будет жить в корне репозитория, рядом с
  `old-sphere/`, а не внутри неё.
- `docs/` — документация *текущего* состояния `old-sphere/`, написанная в
  ходе первого прохода документирования. Сначала читайте
  [docs/README.md](docs/README.md) — это индекс по документам подсистем
  (игровой движок, мульти-мировая архитектура, админ-панель, биллинг,
  портальная CMS, утилиты, фронтенд).
- `REDACTED_CREDENTIALS.txt` (корень репозитория, в `.gitignore`, только
  локально) — сопоставляет каждый плейсхолдер `REDACTED_DB_PASSWORD` /
  `REDACTED_API_SECRET` в `old-sphere/` с реальным значением, которое там
  было до публикации репозитория. Если для реального подключения к чему-либо
  нужен настоящий секрет — смотрите туда, никогда не придумывайте
  правдоподобное значение самостоятельно.

## Критично: секреты в `old-sphere/`

В исходной кодовой базе были десятки захардкоженных паролей БД и платёжных
API-секретов, разбросанных по множеству файлов (найдены в несколько
отдельных проходов, не все по одному паттерну именования — где-то
`'password' => '...'`, где-то `$pass = '...'`, где-то `$secretkey = '...'`
или `define('...ApiSecretKey...', '...')`). Все найденные экземпляры
заменены на `REDACTED_DB_PASSWORD` / `REDACTED_API_SECRET` /
`REDACTED_DB_HOST` / `REDACTED_DB_USER`.

**Это НЕ был единый механический проход — считайте зачистку неполной.**
Если при чтении файла в `old-sphere/` вы видите что-то похожее на реальный
секрет, который ещё не заменён на плейсхолдер `REDACTED_*` (строка похожая
на пароль рядом с `host`/`user`/`dbname`, ключ подписи, API-ключ) —
остановитесь и сначала отредактируйте её так же, как это сделано в
остальном коде, прежде чем продолжать работу с этим файлом. Не просто
задокументируйте находку — обновите `REDACTED_CREDENTIALS.txt` с тем, что
нашли и почему.

## Известный инцидент: не повторять

Две папки, `fr/` и `securite/`, были обнаружены при документировании как
не имеющий отношения к проекту фишинг-прокси в реальном времени,
имитирующий интернет-банкинг Desjardins и CIBC (датирован ~2010-2011 годом,
след взлома хостинга в прошлом — к самой игре отношения не имеет). Они были
удалены и полностью вычищены из истории git (`git filter-branch` +
force-push). Подробности: [docs/portal-cms.md, раздел 3.4](docs/portal-cms.md).
Если где-то ещё в `old-sphere/` встретится похожий необъяснимый контент
(файлы/пути, не вписывающиеся в структуру игры, брендинг чужих банков,
паттерны сбора учётных данных) — остановитесь и сообщите об этом, а не
просто задокументируйте как курьёз.

## Работа с легаси-кодом

- Большинство PHP-файлов в `old-sphere/` в кодировке **Windows-1251**
  (русские комментарии выглядят как кракозябры при чтении в UTF-8/бинарном
  режиме). Используйте `iconv -f CP1251 -t UTF-8`, когда нужно точно
  прочитать кириллические комментарии.
- Автозагрузчика в современном смысле нет — классы подгружаются через
  самописные `import()`/`__autoload()` (`ds/include/Import.inc.php`),
  которые резолвят `PREFIX_ClassName` в
  `ds/classes/PREFIX/PREFIX_ClassName.class.php`. Подробности:
  [docs/game-engine.md](docs/game-engine.md).
- Один код обслуживает три параллельные версии сайта (Classic/Unlimited/
  Pulsar), переключение — через `posix_getuid()` процесса веб-сервера в
  `ds/config/settings.php`, у каждой версии свой список БД игровых миров.
  Подробности: [docs/multi-world-architecture.md](docs/multi-world-architecture.md).
- Игровые миры работают на **PostgreSQL**, несмотря на MySQL-подобные ключи
  в конфиге; портальный/locking-слой и CMS сайта (`sys/`) реально работают
  на **MySQL**. Не считайте, что для всей кодовой базы одна СУБД.
- В портальном слое используются устаревшие `mysql_*`-функции (не
  `mysqli`/PDO), в игровом движке — `pg_*` напрямую (без ORM/query builder).

## Деплой правок в `old-sphere/` на прод

Владелец проекта дал доступ на прямой деплой на живой хостинг
destinysphere.ru — не нужно спрашивать разрешения на каждый деплой
отдельно, если пользователь уже попросил внести правку на сайт.

- **Доступ**: обычный FTP (не SFTP, без шифрования, порт 21). Логин/пароль
  — в `ftpaccess.txt` в корне репозитория (в `.gitignore`, только
  локально). Если файла нет — спросите владельца.
- **Процесс для каждого изменяемого файла** (обязательно в этом порядке):
  1. Скачать текущую live-версию файла с FTP и сравнить с
     `git show HEAD:<path>`. Если отличается — сначала разберитесь, почему
     (возможны правки мимо git), не перезаписывайте вслепую.
  2. Сохранить копию live-версии в `.ftp-backups/<basename>.<timestamp>.bak`
     (каталог в `.gitignore`).
  3. Залить новую версию файла по FTP.
  4. Скачать её обратно и сверить побайтово (`diff`) с локальным файлом —
     деплой считается подтверждённым только после этого, не раньше.
  5. Закоммитить и запушить в git **после** подтверждённого деплоя (проверьте
     `git fetch` + `git log HEAD..origin/main` перед пушем — несколько раз
     были параллельные пуши из других сессий).
- **Кодировка** — см. раздел выше про CP1251: большинство `.php`/`.tpl` в
  Windows-1251, часть исторически в CRLF (не связано с содержимым). Перед
  правкой любого такого файла проверяйте `sum(1 for b in data if b>127)` —
  число не-ASCII байт не должно поменяться, если вы сами не добавляли новый
  кириллический текст. **Никогда не используйте Edit/Write напрямую на
  CP1251-файле, если в нём уже есть не-ASCII байты** — эти инструменты
  читают/пишут в UTF-8 и молча превращают всю остальную кириллицу в файле
  в `\xef\xbf\xbd` (проверено на практике, случалось дважды за одну сессию).
  Вместо этого — `LC_ALL=C sed` для простых замен, или Python с
  побайтовым чтением/записью (`open(path,'rb')`/`'wb'`) и
  `new_text.encode('cp1251')` для нового текста, с проверкой
  `data.decode('cp1251') == new_text` перед записью.
- **Smarty-шаблоны (`.tpl`)**: любой сырой `{`/`}` вне Smarty-тега (CSS,
  JS-объекты вроде `{gc: 1}`) обязан быть обёрнут в `{literal}...{/literal}`
  — иначе Smarty пытается распарсить это как свой тег, компиляция шаблона
  падает, и страница отдаёт пустой ответ или 500 без внятной ошибки в
  браузере (эта ошибка уже дважды ловилась в бою в этой сессии). Перед
  каждым деплоем `.tpl`-файла проверяйте, что количества `{literal}`/
  `{/literal}` и `{if}`/`{/if}` совпадают.
- **Главная страница портала** (`old-sphere/index.php`) рендерит контент
  из БД (`Templates.Body`), статического файла вёрстки для неё нет — все
  визуальные фиксы делаются как `str_replace`/`preg_replace` на буфер
  `$strOut` внутри `index.php`, перед `$pageCache->set()`. `?nfs=79` в URL
  обходит файловый кеш страницы для проверки после деплоя.
- Смотрите `git log` в `old-sphere/` за примерами реальных коммитов деплоя
  — они показывают паттерн куда подробнее, чем этот список.
- **Никогда не удаляйте файлы на проде (FTP DELE/RMD и т.п.) без явного
  разрешения владельца на этот конкретный файл/действие.** Перезапись
  существующего файла новым содержимым по established-процессу выше —
  это ОК и не требует переспрашивать каждый раз, но удаление — отдельное,
  необратимое действие, и его нужно подтверждать отдельно, даже если файл
  кажется мёртвым/неиспользуемым. Если подозреваете, что что-то на проде
  пропало не по вашей вине (см. инцидент с `ds/templates/` и ~26 файлами
  в `ds/` в сентябре 2026 — целая директория и россыпь файлов исчезли с
  сервера без видимой причины с моей стороны) — сравните live-листинг
  с git (`comm -23 <(find old-sphere/X -type f | ...) <(curl ftp listing)`,
  не забыв обрезать `\r` из FTP-вывода) и восстановите из git побайтово,
  но это про ВОССТАНОВЛЕНИЕ уже существующего/закоммиченного состояния,
  а не про удаление.

## Стиль для дальнейшей документации

- Пишите документацию на русском — как уже существующие файлы в `docs/`, и
  на языке владельца проекта.
- Ссылайтесь на конкретные `file.php:строка`, где это возможно — эти
  документы задуманы как навигируемые, а не только описательные.
- Явно помечайте предположения («предположительно» / «не установлено»),
  а не выдавайте догадку за факт — существующие документы аккуратны в этом,
  и новые должны соответствовать тому же стандарту.
